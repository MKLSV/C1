# Архитектура платформы, стек и нефункциональные требования

> Техническая подготовка перед сборкой бота: из чего собирать, как течёт
> запрос, что с приватностью и безопасностью. Стек — рекомендация под доступные
> инструменты; легко заменяется.

---

## 1. Рекомендуемый стек

| Слой | Выбор | Почему |
|------|-------|--------|
| Фронтенд | **Next.js (React) + Tailwind**, чат-интерфейс | быстрый старт, SSR, легко деплоить |
| Хостинг | **Vercel** | доступен как MCP, бесшовно с Next.js |
| Бэкенд | Next.js API routes / Edge Functions | один репозиторий, просто |
| БД | **Supabase (Postgres)** | доступен как MCP; схема уже под Postgres |
| Auth | Supabase Auth | email/OAuth из коробки |
| LLM | **Claude API** (Opus 4.8 — качество диалога; Sonnet 4.6 — эконом) | сильный эмпатичный диалог и рассуждения |
| Кэш промпта | Anthropic prompt caching | дешевле длинные диалоги |

Альтернатива: любой бэкенд (Node/Python/FastAPI) + Postgres — схема и промпт
переносимы.

---

## 2. Поток одного хода диалога

```
Пользователь → Frontend (чат)
   → POST /api/turn { session_id, message }
      → загрузить sessions.profile + последние N messages
      → собрать prompt: [system] + history + [профиль] + [каталог?]
      → Claude API → JSON { reply, stage, profile_patch, ready_to_finalize, needs_catalog_query }
      → merge profile_patch в sessions.profile (deltas суммируются)
      → если needs_catalog_query: matching → подложить каталог в след. ход
      → если ready_to_finalize: записать recommendations
      → сохранить messages (user + assistant)
   ← вернуть reply (и, на финале, отчёт)
Frontend показывает reply
```

Подробности контракта — в [`system-prompt.md`](./system-prompt.md);
матчинг — в [`matching-algorithm.md`](./matching-algorithm.md).

---

## 3. Компоненты бэкенда

- **Turn handler** — оркестрация хода (см. поток выше).
- **Profile merger** — слияние `profile_patch` (deltas, массивы, перезапись).
- **Matcher** — скоринг каталога + диверсификация выдачи.
- **Catalog service** — запросы к `occupations` и связям.
- **Report builder** — сборка финального отчёта из `recommendations`.
- **Safety filter** — детектор кризисных сигналов (см. §5).

---

## 4. Состояние и масштабирование

- Источник истины состояния — `sessions.profile` (JSONB). LLM-вызовы
  stateless: профиль передаётся целиком каждый ход (история реплик усекается,
  профиль — нет).
- Идемпотентность: один `message` → один ход; защищаться от двойных сабмитов.
- Стоимость: prompt caching на системный промпт и каталог; для длинных сессий
  суммаризировать раннюю историю.

---

## 5. Безопасность и этика (встроить с самого начала)

- **Кризисные сигналы.** Детектор слов/смыслов про отчаяние, тяжёлое выгорание,
  само­повреждение → бот выражает заботу и предлагает живого специалиста; не
  продолжает профориентацию «как обычно». Хранить список ресурсов помощи.
- **Без гарантий заработка.** Формулировки — «ориентир», «обычно», «зависит от
  усилий и рынка». Никаких обещаний дохода.
- **Не диагноз.** Явный дисклеймер: инструмент поддерживает выбор, не заменяет
  психолога/карьерного консультанта.
- **Антипредвзятость.** Не сужать по полу/возрасту/происхождению; следить, чтобы
  каталог и формулировки не закрепляли стереотипы (напр. «женские/мужские»
  профессии).
- **Прозрачность.** Сообщать, что это AI; давать увидеть, на основании чего
  сделаны выводы (rationale со ссылкой на ответы).

---

## 6. Приватность и данные (важно — собираем чувствительное)

Платформа собирает персональные данные о человеке (интересы, навыки, доход,
жизненная ситуация). Требования:
- **Согласие** на обработку до начала диалога; понятная политика.
- **РФ — 152-ФЗ** «О персональных данных» (если аудитория в РФ): локализация
  хранения ПДн на серверах в РФ, согласие, право на удаление.
- **ЕС — GDPR** (если есть пользователи в ЕС): правовое основание, право доступа/
  удаления, минимизация.
- **Минимизация:** не требовать ФИО/контакты без необходимости; анонимные сессии
  возможны.
- **Удаление:** дать пользователю удалить сессию/профиль.
- **LLM-провайдер:** проверить, что данные не используются для обучения; включить
  соответствующие настройки/договор (Anthropic — данные API по умолчанию не идут
  в обучение). Не отправлять в LLM лишние идентификаторы.
- **Шифрование** at-rest (Supabase) и in-transit (TLS).

---

## 7. Аналитика и улучшение

- Логировать `recommendations.reaction` и `objection` → калибровка весов
  матчинга.
- Метрики качества: доля сессий, дошедших до финала; число «живых» гипотез;
  субъективная оценка пользователя («насколько попало?»).
- A/B на формулировках вопросов из банка (`questions`).

---

## 8. Минимальный набор экранов (MVP)

1. Лендинг + согласие на обработку данных.
2. Чат-экран (один диалог).
3. Экран результата: 3–5 карточек профессий (формат, доход, путь входа, первый
   шаг) + кнопка «сохранить/отправить на почту».
4. (Опц.) Личный кабинет с историей сессий.

# Фаза 3 — Матчинг и итоговый результат

> Цель: превратить собранный профиль в ранжированный список конкретных
> профессий и понятный итоговый отчёт с первым шагом.

## Результаты фазы

- **Matcher** — реализация скоринга из `docs/matching-algorithm.md`.
- Диверсификация выдачи (и наём, и своё дело; не более 2 на один RIASEC-тип;
  +1 «расширяющий горизонт»).
- Подкладывание топ-N ролей в контекст бота по `needs_catalog_query`.
- **Report builder** — финальный отчёт из `recommendations`: по каждой роли
  «почему вам» (rationale со ссылками на ответы), формат, доход, путь входа,
  Ikigai-сведение, один первый шаг.
- Сохранение `recommendations` (с реакцией пользователя для калибровки).

## Задачи

- [ ] Реализовать компоненты скоринга: riasec_similarity (косинус),
      skills_overlap, format_match, income_fit, values_overlap, demand_bonus,
      penalty_big_five.
- [ ] Вынести веса в конфиг (для калибровки в Фазе 6).
- [ ] Диверсификатор выдачи + подбор «расширяющего горизонт» из
      `occupation_relations`.
- [ ] `explain()` → текст rationale на основе совпадений профиля и роли.
- [ ] Выбор лучшего `entry_path` под формат пользователя → `first_action`.
- [ ] Генерация итогового отчёта (структура карточек) на этапе wrapup.
- [ ] Обработка холодного старта/пробелов (мало данных → не финализировать).

## Что собрать / решить

- Стартовые веса формулы (взять из matching-algorithm.md, потом калибровать).
- Формат итогового отчёта в UI (Фаза 4) — карточки/PDF/email.
- Сколько вариантов показывать (рекоменд. 3–5).

## Зависит от

Фаза 1 (каталог) и Фаза 2 (профиль). Тесно работает с ботом.

## Критерий готовности

- На 5–10 тестовых профилях matcher выдаёт осмысленные, разнообразные роли.
- В каждой выдаче есть и наёмный, и самозанятый вариант.
- Отчёт содержит для каждой роли: почему/формат/доход/путь/первый шаг.
- Реакции на гипотезы сохраняются в `recommendations`.

## Оценка

Средняя по объёму; критична для «попадания» рекомендаций.
